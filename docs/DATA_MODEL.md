# FairResolve Data Model & Durability Architecture

## 1. Overview & Principles

FairResolve separates data into three distinct operational domains:
1. **Tenant & Identity Domain**: Organizations, Operators, Sessions, and Role-Based Access Controls (RBAC).
2. **Transactional & Dispute Domain**: Orders, Dispute Cases, Evidence Files, and Deterministic Store Policies.
3. **Financial & Audit Domain**: PayPal Refund Execution Attempts, Outbox Queue, and Tamper-Evident Hash-Chained Audit Logs.

### Epistemic Labeling in Data Structures
Every recorded fact in FairResolve carries an immutable provenance indicator:
- `CUSTOMER_REPORTED`: Unverified buyer assertions.
- `PAYPAL_VERIFIED`: Cryptographically signed or API-verified transaction records directly from PayPal Sandbox.
- `MERCHANT_PROVIDED`: Internal fulfillment and catalog records.
- `EVIDENCE_RECEIVED`: SHA-256 fingerprinted uploaded assets with magic byte verification.
- `AI_OBSERVATION`: Epistemic multimodal observations generated by Gemini Flash. Never equated to fact.
- `POLICY_RULE`: Deterministic, code-enforced store policy thresholds.
- `HUMAN_APPROVAL`: Explicit cryptographic operator authorization.

## 3. Storage & Durability Strategy

### Atomic Persistence Engine
In containerized and local deployments where a managed database instance is external, FairResolve uses an atomic file persistence engine:
1. State is serialized to JSON in memory.
2. Written to a temporary file (`./data/fairresolve_db.json.tmp.<pid>.<timestamp>`).
3. `fs.fsyncSync` forces file buffers to physical media.
4. `fs.renameSync` performs an atomic filesystem inode replacement.
5. In the event of sudden container termination or power disruption, the previous durable state remains intact without partial file corruption.

### Production PostgreSQL Migration
When migrating to production Cloud SQL or RDS PostgreSQL, FairResolve includes complete DDL schemas in `docs/DEPLOYMENT.md` with standard B-Tree indexes on:
- `tenants(id)`
- `users(tenant_id, email)`
- `sessions(token_hash)`
- `orders(tenant_id, paypal_capture_id)`
- `cases(tenant_id, status)`
- `evidence(sha256_hash)`
- `refund_attempts(idempotency_key)`
- `audit_events(case_id, timestamp)`
